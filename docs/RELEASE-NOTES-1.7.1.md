# LedgerTB v1.7.1

Released September 5, 2026.

This update fixes recurring-entry approval so a prepared draft keeps the
instructions and supporting reference it had when it was generated.

## Fixes

- Changing a schedule's reversal setting no longer changes whether an existing
  draft creates a reversal when approved. Future drafts use the updated setting.
- Renaming a template or changing its workpaper reference no longer changes the
  name and reference used when an existing recurring draft posts.
- Refreshing an authorized browser window after navigating between pages keeps
  the window authorized. Windows without the launch token remain blocked.
- Assistant integrations can read each draft's entry type, including Adjusting
  and Beginning Balance, through the MCP draft-list response.

## Upgrading from v1.7.0

Create a verified backup in Data Safety and close LedgerTB before installing
the update. Existing books receive migration 025 when opened.

Pending primary drafts generated by a recurring schedule before this update
do not contain the stored reversal instruction and template reference needed
for reliable approval. LedgerTB explains this and blocks their approval.
Reject the old draft, review the template and schedule settings, then regenerate
the period and review the replacement before approving it.

An older pending reversal draft can still be reviewed and approved: it already
contains its amounts, date, and link to the original posted entry. Posted
entries remain unchanged. This update does not repair entries already approved
under v1.7.0; review any affected postings through the normal correction workflow.

## Verification

The release adds 20 Python test cases covering recurring snapshots, populated
prior-schema upgrades, an accounting workflow, abrupt process termination, and
the real MCP transport. Browser acceptance exercises unlock, client switching,
schedule edits, approval, reversal, and refresh, then checks the saved postings.

The pinned Mac suite passed 721 tests with 5 Windows-specific skips, including
both performance tests. The pinned Windows suite passed 722 tests with 2 skips
and both performance tests excluded. GitHub's Linux suite passed 719 tests
with 5 skips and both performance tests excluded. The corrected browser
scenario passed in two hosted runs, and security checks passed.

The Mac app is Developer ID signed, Apple-notarized, and stapled; frozen
selfcheck, gzip-requested HTTP routes, graceful server shutdown, signature
verification, and Gatekeeper assessment passed. The Windows build passed
encryption, frozen selfcheck, startup/shutdown, and installer packaging checks.

This release proceeds on the completed automated verification. Hands-on native
installation and upgrade checks were not completed. See [Testing](TESTING.md) and
[Windows testing](WINDOWS-TESTING.md).
